# SoundThere

A Kotlin Multiplatform (Compose) front end for the SoundCraft engine, built the way Loki Text is built for
WordCraft: a thin UI that runs the engine's commands by id over a six-function C ABI. It is separate from
the egui front end and shares only the Rust engine.

```
Compose UI (app/, Kotlin, on Loki Kit)  ──  JSON commands  ──  C ABI (JNA)  ──  loki-ffi (ffi/, Rust)  ──  `soundcraft_automation::Headless`
```

How it was made, and how to continue: Loki Text's
[playbook](https://github.com/AppThere/loki-text/blob/main/loki-text/docs/kmp-responsive-ui-playbook.md)
and [`egui2compose`](https://github.com/AppThere/loki-text/blob/main/loki-text/docs/egui2compose.md)
(in the `loki-text/` folder of the WordCraft fork).

## What it does

* **Every engine command is reachable**: the menu bar, the all-commands list and a generated form for each
  command's parameters, from the engine's own command list. A test fails if one has no way to it.
* **The surface** is nothing the engine renders: it has no picture of the arrangement, so the app draws it from `session.inspect` (`Arrangement.kt`): the tracks, their clips, the markers, the selection and the playhead.
* **The window**: the Tracks panel (mute, solo, record arm and volume for each track), the Clip List and the Markers; the transport and the new-track and marker buttons on the options bar; File › Open Session…, Import Audio…, Save.
* **Phone, tablet and desktop** layouts from one code base; menus open as a sheet on a phone or tablet.

## What it does not do yet

**It does not play or record sound**: the headless session has no audio engine, so the transport moves nothing and the playhead stays where it is put. Clips are blocks with their names; no waveforms are drawn. No clip dragging or trimming on the arrangement yet.

## Layout

- `Cargo.toml`, `ffi/`: its own Cargo workspace (the engine workspace forbids `unsafe`; the FFI crate
  needs it). `ffi/src/lib.rs` is the same in every Craft front end of this kind; `ffi/src/app.rs` is what
  is this engine's own. Header: `ffi/include/loki.h`.
- `app/`: the Gradle project generated by `egui2compose.py`, on Loki Kit (`app.loki:kit`, included from
  `../../loki-text/loki-text`, so the WordCraft fork must be checked out beside this repository). `AppParts.kt`
  is this app's own (panels, options bar, file actions); `jnaMain` has the JNA binding, `androidMain` the activity.
- `REPORT.md`: what the generator read from the egui front end and what it could not translate.

## Run

```sh
scripts/build-desktop.sh run               # cargo build --release -p loki-ffi, then gradle :app:run
scripts/install-desktop.sh                 # install on this machine (Linux): a launcher and a menu entry
VARIANT=Release scripts/build-android.sh   # libloki_ffi.so for arm64-v8a and x86_64, then the APK
adb install -r app/build/outputs/apk/release/app-release.apk
cargo test -p loki-ffi --release           # the C ABI: hostile arguments, command state, surface
gradle :app:jvmTest                        # the coverage test: every engine command has a way to it
LOKI_SHOTS=/tmp/shots gradle :app:jvmTest --tests '*CoverageTest*' --rerun   # phone, tablet, desktop PNGs on the real engine
```

Use Gradle 9.1 with JDK 21. After an engine change:
`LOKI_UPDATE_FIXTURES=1 cargo test -p loki-ffi --release kotlin_command_fixture`, then `gradle :app:jvmTest`.

## Status (November 2026)

Verified on Linux x86_64 (JVM desktop): the FFI tests, the Gradle coverage test and off-screen renders on the
engine's own library. The release APK (arm64-v8a and x86_64, signed with the debug key so it installs on
one's own devices) installs and launches on a Pixel 9; use on the device has not been checked beyond launch.
iOS has not been built.

## Rules

The repository's rules hold here: never crash (the FFI layer catches panics and returns errors; the Kotlin
side degrades on a bad reply), and no Microsoft, Adobe, Avid or Autodesk assets. No asset files are added;
the Lucide icons are a dependency (ISC).
